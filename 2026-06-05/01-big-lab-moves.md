## 3. Claude Opus 4.8 — dynamic workflows, ultracode mode, ~4× honesty improvement {#3-opus-4-8}

**What happened:** On **May 28, 2026** (41 days after Opus 4.7), **Anthropic released Claude Opus 4.8** — with three things that change the *primitive* of how you work with Claude:

1. **Effort controls in claude.ai** — `/effort low | medium | high | xhigh | ultracode` — gives you direct manual control over reasoning depth.
2. **Dynamic workflows in Claude Code (research preview)** — say *"workflow"* in your prompt (or set `/effort ultracode`) and Claude writes a **JavaScript orchestration script** that a separate runtime executes, **spawning dozens to up to 1,000 parallel subagents** that each verify their outputs before returning. Demoed primitive: **codebase-scale migrations across hundreds of thousands of LOC from kickoff to merge in a single session.**
3. **Cheaper "fast mode"** + **dynamic workflows on Max / Team / Enterprise plans, plus API**.
4. **Honesty:** *~4× less likely than Opus 4.7 to let a coding flaw slip through unflagged.*
5. Standard pricing **unchanged** from Opus 4.7.

- [TechCrunch — Anthropic releases Opus 4.8 with new "dynamic workflow" tool](https://techcrunch.com/2026/05/28/anthropic-releases-opus-4-8-with-new-dynamic-workflow-tool/) `[secondary]`

### Why it matters to you

- **Job lens:** Two interview answers got rewritten in one release. (1) *"How do you parallelize a coding agent at scale?"* — the right answer is now **"design a dynamic workflow with `/effort ultracode`, define the verification step explicitly, and budget per-subagent cost"**, not "spawn subagents manually." (2) *"How do you reduce hallucinations in code?"* — point at the **~4× honesty number** in Anthropic's own writeup and discuss the verification-before-return primitive. Drop both into your portfolio README this weekend.
- **Startup lens:** Dynamic workflows are a *runtime*, not just a model — and that runtime exposes the **per-subagent cost-trace surface**. The cleanest founder wedges right now are (i) **cost dashboards / budget guards over dynamic workflows**, (ii) **eval harnesses that benchmark a workflow's output against a held-out spec**, (iii) **shape templates ("dependency upgrade workflow," "framework migration workflow," "security audit workflow") that ship the script + the eval together**. Anthropic owns the runtime; everyone else can build over it.
- **Insight:** This is *not* "Opus 4.8 is 7% better on a benchmark." This is **Anthropic moving from a model business to an agent-runtime business** — model + script-writer + executor + verifier as one product. The right reading is *the [Karpathy-team mandate from 2026-05-22](../2026-05-22/01-big-lab-moves.md#3-karpathy) — "use Claude to build Claude" — applied externally as a customer product*. Opus 4.8 is the first model where the model writes the program that uses the model. Treat it that way.
