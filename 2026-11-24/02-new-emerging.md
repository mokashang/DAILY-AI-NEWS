## 6. llama.cpp v1.0.0 stable — semantic versioning + 150+ model architectures

**What happened.** **llama.cpp**, the C/C++ runtime that quietly powers most open-weight LLM deployments, **shipped v1.0.0 stable** this week. Switch to **semantic versioning**, **150+ supported model architectures**, and a formal commitment to a stable API surface for downstream packagers (Ollama, LM Studio, Jan, local-first apps).

**Sources.** [aggregator] AI Weekly Nov 22 ("llama.cpp Ships v1.0.0 Stable With Semantic Versioning and 150+ Supported Model Architectures"); [primary] [llama.cpp on GitHub](https://github.com/ggerganov/llama.cpp).

**Why it matters to you.**
- **Job.** **"I run production inference on llama.cpp"** is a different résumé line than **"I prompt Fable well."** If you want AI-infra jobs that pay at $200–260K base without a PhD, this is the lane. Study GGUF quantization, batching strategies, speculative decoding — the open-weight runtime is now the GPU-economy's **actual workhorse**.
- **Startup.** With llama.cpp 1.0 + **non-US frontier open-weight models (Kimi K3 / GLM 5.3 / Qwen 3.8)**, a startup can plausibly **ship with zero US-API dependency**. Compliance-driven markets (EU, healthcare, finance, government) are the first to take this seriously. Pick a vertical where data-residency is binary and build on this stack.
- **Insight.** Three things are converging: **(a)** open-weight frontier is non-US, **(b)** llama.cpp is API-stable, **(c)** NVIDIA Rubin ships before EOY. The **"sovereign AI stack"** (non-US model, open runtime, your own GPUs) is for the first time a **real production configuration**, not a ideology.
